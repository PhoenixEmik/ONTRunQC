# Benchmarking

## Measurements in this environment

Measured on 2026-10-16 with the release build, Rust 1.98.1, macOS arm64, default
system allocator, and local files. Each row represents one timed execution;
these are observations, not throughput guarantees. No real research records or
identifiers are included in this repository.

| Input | Size (bytes) | Records | Wall (s) | User CPU (s) | System CPU (s) | Peak RSS (MiB) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Supplied PromethION fixture | 366,182 | 1,000 | 0.3866 | 0.006550 | 0.009275 | 2.61 |
| Synthetic scale test | 1,599,749,860 | 30,549,981 | 8.7736 | 8.525951 | 0.236408 | 476.30 |

Peak RSS in bytes: 2,736,128 for the fixture; 499,433,472 for the synthetic run.

The supplied `promethion_fixture.tsv` contains 999 basecalled reads, one
zero-length row, and 4,714,853 bp of yield. An independent Python `csv`/`statistics`
calculation matched overall counts, exact length median/N50, quality statistics,
channel/mux/reason counts and yields, both histograms, and cumulative time-bin
yield. The fixture is too small for a meaningful throughput estimate; startup and
filesystem effects dominate its elapsed time.

The scale input is entirely synthetic, with a repeated 1,000-row pattern of
varying read lengths, Q-scores, channels, muxes, filtering, reasons, and unsorted
start times. All 30,549,981 records are basecalled, exercising full storage of both
length and Q-score vectors. Total yield (473,081,441,871 bp), exact N50, both
medians, and mean quality were independently checked using weighted pattern
counts. Repeated executions generated byte-identical reports.

This synthetic input is repetitive and substantially smaller than the real
approximately 11 GB file. It exercises the target record count and memory path,
but does not establish performance on real PromethION data. The full
`sequencing_summary_PBM96073_e70444ee_4b72c09a.txt` was not available in this
environment. Benchmark it on the actual HPC system before claiming the
below-512-MiB real-run RSS target is met.

macOS `/usr/bin/time -v` is unavailable; `/usr/bin/time -l` could not finish
resource reporting because `sysctl kern.clockrate` was restricted. The table
uses Python `time.perf_counter()` around a checked `subprocess.run`, and
`resource.getrusage(resource.RUSAGE_CHILDREN)` in a fresh Python process for each
execution. On macOS `ru_maxrss` is bytes; Linux reports KiB. Resource accounting
does not include the Python parent. Memory and wall-clock results depend on the
allocator, filesystem/cache state, and competing workloads.

## Full-run procedure on Linux/HPC

Use a dedicated CPU and sufficient memory to observe rather than terminate runs
that exceed the target. Record CPU model, RAM allocation, filesystem/storage,
Rust/compiler version, build revision, and whether the input was already cached.
Use release mode and the committed lockfile:

```sh
cargo build --release --locked
mkdir -p benchmark-results
summary_path=/path/to/sequencing_summary_PBM96073_e70444ee_4b72c09a.txt
wc -c < "$summary_path" > benchmark-results/input-bytes.txt
rustc --version > benchmark-results/rust-version.txt
uname -a > benchmark-results/system.txt
/usr/bin/time -v -o benchmark-results/time.txt \
  target/release/ontrunqc analyze "$summary_path" \
  --output benchmark-results/qc/
```

The GNU time output includes elapsed wall time, user CPU, system CPU, and maximum
resident set size in KiB. Preserve the exit status and inspect errors before
using any previous report. Validate the current report:

```sh
python3 - <<'PY'
import json
from pathlib import Path
r = json.loads(Path('benchmark-results/qc/report.json').read_text())
m = r['metrics']
assert m['total_records'] == 30_549_981
assert m['basecalled_reads'] <= m['total_records']
assert m['passed_reads'] <= m['basecalled_reads']
assert m['passed_yield_bp'] <= m['total_yield_bp']
assert m['basecalled_reads'] + m['zero_length_records'] == m['total_records']
assert m['passed_reads'] + m['failed_reads'] == m['basecalled_reads']
assert m['passed_yield_bp'] + m['failed_yield_bp'] == m['total_yield_bp']
for key in ('channels', 'muxes', 'end_reasons'):
    assert sum(x['total_records'] for x in r[key]) == m['total_records']
    assert sum(x['total_yield_bp'] for x in r[key]) == m['total_yield_bp']
assert sum(x['yield_bp'] for x in r['time_bins']) == m['total_yield_bp']
assert r['time_bins'][-1]['cumulative_yield_bp'] == m['total_yield_bp']
assert sum(x['read_count'] for x in r['quality']['histogram']) == m['basecalled_reads']
assert sum(x['read_count'] for x in r['read_length_distribution']) == m['basecalled_reads']
assert sum(x['yield_bp'] for x in r['read_length_distribution']) == m['total_yield_bp']
print('Validated records:', m['total_records'])
PY
```

Repeat at least three times, retaining each timing separately. Compare report
bytes with `cmp`; there should be no run timestamps or ordering changes. Report
all measurements and distinguish cold-cache from warm-cache runs. Do not copy
the research input or identifying JSON report into version control.

## Reproducing the synthetic input

This creates approximately 1.60 GB on disk; keep it outside the repository:

```sh
python3 - <<'PY'
from pathlib import Path
n = 30_549_981
header = ('run_id\tchannel\tmux\tstart_time\tduration\tpasses_filtering\t'
          'sequence_length_template\tmean_qscore_template\tend_reason\n')
rows = []
for i in range(1000):
    flag = 'TRUE' if i % 2 else 'FALSE'
    reason = 'normal' if i % 3 else 'other'
    rows.append((f'scale-run\t{i%3000+1}\t{i%4+1}\t{(i*173)%86400}.5\t1.0\t'
                 f'{flag}\t{i*31+1}\t{(i*7)%50}.{i:03}\t{reason}\n').encode())
with Path('/tmp/ontrunqc-synthetic-scale.tsv').open('wb') as f:
    f.write(header.encode())
    block = b''.join(rows)
    for _ in range(n // 1000):
        f.write(block)
    f.write(b''.join(rows[:n % 1000]))
PY
```

Time the CLI with that path as input. Use a fresh timing process; exclude input
generation and compilation. The expected record count is 30,549,981, input size
is 1,599,749,860 bytes, and zero-length count is zero.
